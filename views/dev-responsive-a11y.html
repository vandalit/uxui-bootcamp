Responsive y accesibilidad técnica

Que la interfaz se adapte a cualquier tamaño de pantalla y que cualquier persona pueda usarla, incluyendo quienes navegan con teclado o con un lector de pantalla.

Mobile-first

Diseñar y maquetar primero para pantallas pequeñas, y agregar complejidad para pantallas grandes con media queries — en vez del camino inverso.

Unidades relativas

%, rem, em, vw/vh escalan según el contexto (tamaño de fuente raíz, viewport), a diferencia de px, que es fijo.

ARIA

Atributos (aria-label, aria-hidden, role) que describen el propósito de un elemento a un lector de pantalla cuando el HTML semántico no basta.

Contraste de color

Diferencia de luminosidad entre texto y fondo, medida en ratio (ej. 4.5:1 mínimo en WCAG AA) — sin suficiente contraste, el texto es difícil o imposible de leer.

Navegación por teclado

Todo elemento interactivo debe poder alcanzarse con Tab y activarse con Enter/Espacio, con un foco visible que indique dónde se está.

Texto alternativo

El atributo alt describe una imagen para quien no puede verla — también permite que el contenido se entienda si la imagen no carga.

Anatomía de un botón accesible

<button aria-label="Cerrar">×</button>
Elemento nativo, ya enfocable con teclado Describe el propósito para quien no ve el ícono Contenido visual (el símbolo ×)

Un <button> nativo ya trae foco y activación por teclado gratis — el aria-label cubre lo que el ícono no comunica por sí solo a un lector de pantalla.
