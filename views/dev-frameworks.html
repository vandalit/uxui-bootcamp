Frameworks — lo básico

Conjuntos de CSS y componentes ya construidos (grid, botones, formularios, navegación) sobre los que se construye más rápido — a cambio de menos control fino sobre el detalle visual.

Grid de columnas

Sistema de 12 columnas (o similar) con clases como col-6 o col-md-4 para repartir el ancho sin calcular porcentajes a mano.

Clases utilitarias

Clases pequeñas y reutilizables que aplican un solo estilo — mt-3 (margen superior), text-center, d-flex — en vez de escribir CSS propio para cada caso.

Componentes listos

Botones, tarjetas, modales, navbars y formularios ya diseñados y funcionales — se usan agregando una clase, sin escribir el componente desde cero.

Velocidad vs. control

Un framework acelera el desarrollo y da consistencia de fábrica, pero personalizar a fondo el detalle visual suele requerir sobrescribir sus estilos por defecto.

Otros ejemplos

Bootstrap es el más conocido, pero existen otros enfoques: Tailwind CSS (solo utilitarias, sin componentes visuales propios), Material UI, Bulma.

Responsive de fábrica

La mayoría de los frameworks ya incluyen breakpoints y comportamiento adaptable a distintos tamaños de pantalla, sin escribir media queries propias.

El mismo botón: CSS propio vs. clases utilitarias

CSS propio
.btn-primario {
  background: #0d6efd;
  padding: 0.5rem 1rem;
}

Una regla nueva, escrita y mantenida a mano.

Clases utilitarias
<button class="btn btn-primary">

Mismo resultado visual, sin escribir CSS propio — el estilo ya existe en el framework.
